# 行情数据源接入

默认模式为 `akshare_tushare`：AKShare 优先，Tushare 备用。应用、策略、盘后结算继续使用统一行情类型，不需要处理数据源切换。

## 配置

在项目 `.env` 中设置：

```dotenv
AI_TRADING_MARKET_DATA_MODE=akshare_tushare
TUSHARE_TOKEN=在本机填写自己的Token
```

AKShare 无需 Token。Tushare 必须注册账号并取得 Token，账号还需具备相应接口权限。不能把“接入免费接口”理解为匿名或无限量调用。Token 由 `SecretStr` 管理；配置保存命令会保留此字段，日志不输出凭据或上游异常正文。

官方权限说明列出的免费档为 120 积分、每分钟 50 次、每日 8000 次，支持非复权日线。额度和权限以账号实际状态及官方文档为准。

## 范围和数据口径

- 当前冗余覆盖沪深 A 股日线，不含实时分时、盘口、港股、ETF 和基金。项目现有港股仍会报告不可用，不用 A 股数据替代。
- 单日 `fetch` 返回不复权 OHLC 和成交股数，停牌或不存在的日期不会用邻近日期填充。
- 策略 `fetch_range` 返回以请求区间最后一根日线为锚的前复权价格，成交量保留实际股数。AKShare 使用后复权数据和末日原始收盘价归一化；Tushare 使用 `daily` 与 `adj_factor`。
- **Tushare 免费档的非复权日线权限不足以保证策略历史备份可用**。缺少 `adj_factor` 权限时，策略历史请求会明确失败，不会把不复权价格混入复权序列。因此免费账号可备份单日日线，但完整策略历史冗余取决于账号权限。
- 两源成交量从“手”统一转换为“股”，拒绝非有限价格、非法 OHLC、证券不匹配、重复日期及区间外数据。区间必须包含交易日历的全部会话；停牌造成的缺口也会拒绝，符合当前连续历史策略的约束。

## 切换行为

1. 每次请求先尝试 AKShare，成功后不访问 Tushare。
2. 网络异常、接口拒绝、空结果、过期日期或校验失败时，尝试 Tushare。
3. 历史请求整体切换，不拼接不同来源的复权价格。
4. 下次请求重新尝试主源，支持主源恢复。
5. 全部失败时返回统一 `MarketDataProviderError`，应用按原有规则转为行情不可用或 HOLD，不伪造行情。

切换是同一请求内的顺序尝试，上游请求配置 20 秒网络超时；SDK 内部可能有多次 HTTP 请求，这不是整个调用的绝对时限。当前没有磁盘行情备份或离线缓存；这里的“备份”是备用数据源。

默认模式由单个有效来源提供行情，取消原 Yahoo/Tiingo 模式“必须双源交叉印证”的要求。它提高可用性，同时无法用第二个来源识别一个格式合法但数值错误的结果。真实来源写入行情记录，健康页面展示持久化观测，不把 Token 已配置视为可用。

## 验证命令

所有操作通过项目脚本执行，日志写入 `logs/`：

```bash
scripts/setup.sh
scripts/test.sh tests/integrations/china tests/application/test_market_failover.py
scripts/check.sh
scripts/jobs/check_china_sources.sh --symbol 600519.SH --trade-date 2026-10-28
scripts/jobs/run_data_smoke.sh --date 2026-10-28
scripts/jobs/run_strategy_smoke.sh --date 2026-10-29
```

两源探测只读，不创建交易计划或订单；任一来源不可用时返回非零状态。`data-smoke` 通过真实应用入口读取自选股，港股会使结果为部分可用。

如需恢复旧的双源质量门，设置 `AI_TRADING_MARKET_DATA_MODE=yahoo_tiingo` 并配置 `TIINGO_API_KEY`。
