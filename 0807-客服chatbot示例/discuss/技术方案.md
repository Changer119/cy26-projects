# 内部客服 Chatbot 技术方案（Agent 分工演示用）

## 需求
面向公司内部员工的客服 chatbot：接入内部知识库做检索增强（RAG），支持多轮对话，
提供 Web 聊天界面 + 后端 API。

## 架构

```
[Next.js 前端: 聊天界面]
        |  HTTP JSON
        v
[Python 后端: FastAPI]
   ├── /api/chat        多轮对话入口
   ├── RAG 检索模块      从向量库取相关知识片段
   └── DeepSeek 调用封装  OpenAI 兼容 SDK
        |
        v
[向量库]  知识库文档 embedding 存储
```

- 前端：Next.js（最新大版本）+ React + TypeScript + Tailwind CSS，纯 Web 聊天界面
- 后端：Python + FastAPI，用 `uv` 管理依赖，虚拟环境目录固定为 `.venv`
- LLM：DeepSeek 模型，`openai` SDK + OpenAI 兼容 API 格式，三个配置项
  （`DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`）全部走环境变量，
  放在 `.env`，`.env.example` 给占位示例
- 检索：知识库文档预先切片、embedding，存入本地向量库（如 Chroma），
  对话时先检索 top-k 片段拼进 prompt 上下文
- 会话管理：`session_id` 对应一段多轮上下文，MVP 阶段存内存/sqlite 即可
- 数据结构：全部走强类型（Pydantic model / TS interface），不用裸 dict

## 接口契约（先定好，后端/前端可并行开工的前提）

```
POST /api/chat
Request:  { "session_id": string, "message": string }
Response: { "session_id": string, "reply": string, "sources": string[] }
          // sources: 命中的知识库片段来源，前端用于展示引用

GET /api/health
Response: { "status": "ok" }
```

## Agent 任务拆分

| Agent | 任务 | 验收标准 |
|---|---|---|
| 后端 Agent | 实现 `/api/chat`、RAG 检索、DeepSeek 调用封装、单元测试 | 用固定测试问题跑通，返回结构符合契约，无硬编码 key |
| 前端 Agent | 聊天界面（消息列表/输入框/引用展示），只依赖上面的接口契约 mock 联调 | 浏览器手动跑一轮多轮对话，UI 无报错 |
| 集成校验（人工/审查 Agent） | 前后端联调、跑端到端多轮对话、检查检索是否命中 | 端到端场景通过，代码审查无坏味道（硬编码、过度设计、裸 dict 等） |

后端和前端两个 Agent 可以并行开工，因为接口契约已经定好，互不阻塞。
集成校验放在两边都完成之后，作为唯一的强制检查点。
